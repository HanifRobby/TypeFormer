  ---
  B. Perbedaan Metrik Scoring (Penting untuk Desain)

  Kode existing (test.py):
  - Menggunakan Euclidean distance (semakin kecil = semakin mirip = genuine)
  - Label EER: 0 = genuine, 1 = impostor (distance-based convention)
  - compute_eer(labels, scores) dengan pos_label=1 → impostor sebagai positive
  class

  Implementation guide (Section 9.8 & 10.1):
  - AS-Norm menggunakan cosine similarity (semakin besar = semakin mirip =
  genuine)
  - Label EER: 1 = genuine, 0 = impostor (similarity-based convention)
  - fpr, tpr = roc_curve(labels, scores) dengan pos_label=1 → genuine sebagai
  positive class

  Implikasi: Ketika wrapper TypeFormer digunakan dalam sistem baru, pipeline
  scoring harus secara eksplisit memilih satu konvensi (guide merekomendasikan
  cosine similarity) dan memastikan EER computation konsisten. Baseline B0 harus
  dijalankan dengan Euclidean (mengikuti paper asli) tapi baseline B1/B2 dan
  seterusnya menggunakan cosine.

  ---
  C. Bug di train.py (Bukan di trainv2.py)

  File train.py:99-108 — fungsi eval_one_epoch() memanggil inner_ops() tanpa 
  argumen mode, sehingga default ke mode='train' yang menjalankan
  optimizer.step() selama validasi. Ini berarti validasi secara tidak sengaja
  melatih model.

  trainv2.py sudah memperbaiki ini dengan memanggil inner_ops(..., mode='eval').
  Guide merekomendasikan trainv2.py sebagai basis, jadi ini bukan blocker untuk
  proyek baru.

  ---
  D. Hardcoded .to('cuda') di TypeFormer Reference Code

  Dua lokasi yang bermasalah untuk portabilitas:

  1. model/Model.py baris 318 dan 326 — Conv1d layers di HARTrans.__init__()
  ditulis .to('cuda') langsung saat inisialisasi:
  torch.nn.Conv1d(...).to('cuda')  # line 318
  torch.nn.Conv1d(...).to('cuda')  # line 326
  2. model/Preliminary.py baris 155 — Gaussian_Position hardcode posisi ke CUDA:
  self.positions = torch.tensor([...]).to('cuda')

  Ini akan error jika dijalankan di CPU-only atau device bukan cuda:0. Karena
  user menyebut sudah melakukan "sedikit modifikasi," kemungkinan ada
  workaround, tapi kode yang ada masih memiliki baris ini. typeformer_wrapper.py
  harus menggunakan torch.load(..., map_location=device) dan memindahkan model 
  ke device yang benar — test.py sudah melakukan ini
  (TransformerModel.to(device)), tapi inisialisasi Conv1d tetap ke CUDA saat
  __init__ dipanggil.

  ---
  Catatan Teknis Penting (Sebelum Plan)

  1. Bug arsitektur Model.py (non-blocker karena CUDA tersedia)

  HARTrans.__init__() menyimpan Conv1d layers dalam Python list biasa
  (self.encoders), bukan nn.ModuleList. Ini berarti model.to(device) tidak
  memindahkan layer tersebut — tapi karena sudah di-hardcode .to('cuda') saat
  __init__, ini hanya bermasalah di CPU. Karena GPU tersedia,
  typeformer_wrapper.py akan selalu menggunakan CUDA dan mendokumentasikan
  constraint ini.

  2. Convention scoring terpadu

  Semua scorer di framework baru mengembalikan nilai "higher = more genuine".
  Untuk B0/B1 (distance-based), scorer mengembalikan nilai negatif dari
  Euclidean distance (-dist). Ini membuat metrics.py seragam tanpa perlu
  special-case.

  3. Genuine probes protocol

  Mengikuti test.py asli: enrollment = sesi [0:E], genuine probes = 5 sesi
  terakhir [-5:] = sesi [10:15], impostor = 1 sesi terakhir ([-1]) dari setiap
  user lain. Tidak ada overlap karena E ≤ 10.

  Detail 02_reproduce_baseline.py (B0):

  1. Load config b0_baseline.yaml
  2. Load TypeFormerWrapper (frozen, float32, CUDA)
  3. Load/compute test set embeddings → cache ke results/embeddings_cache/test/
  4. Per user (1000 users):
     - enrolment_embs = embeddings[user][0:E]   ← sesi 0..E-1
     - genuine_scores = [-euclidean(mean_enrol_emb, probe_emb)
                         for probe in embeddings[user][-5:]]
       ← negate distance → "higher = genuine"
       ← menggunakan MEAN pairwise: mean distance dari E sesi enrolment ke probe
     - impostor_scores = [-euclidean(mean_enrol_emb, embeddings[other][-1])
                         for other in all_other_users]
  5. Hitung per_subject_eer → mean, std
  6. Hitung global_eer dengan bootstrap_ci
  7. Simpan ke results/b0_baseline/metrics.json + per_user_eers.csv

  B0 scoring detail: Mengikuti test.py asli:
  - Template = mean embedding dari E sesi enrolment (bukan mean pairwise dari
  paper, TAPI test.py juga menggunakan mean yang sama dengan cara
  euclidean_distances(enrolment_embs, test_embs) → mean(axis=0) → ini mean
  distance per probe ke semua E embeddings, setara mean pairwise)
  - Implementasi kita: score = -mean_i(euclidean(enrol_i, probe)) for i in 1..E

  Detail user_stats.py:
  compute_user_stats(sessions: ndarray[E,50,5]) → ndarray[20]
    - Concatenate: (E*50, 5) → filter zero-padding rows → valid_keystrokes
  (T_valid, 4)
    - features: kolom 0-3 (HL, IL, IRL, IKT) — kolom 4 (ASCII) dikecualikan
    - statistik: mean(4), std(4), p25(4), p50(4), p75(4) → concat → (20,)
    - edge case E=1: jika T_valid < 10, warning tapi tetap return (tidak crash)

  Hierarki Scorer:
  BaseScorer (ABC)
    .score(e_u, e_p) → float          # single pair
    .score_batch(e_u, probes) → array # one-to-many (optimization)

  RawEuclideanScorer(BaseScorer)     # B0, B1: -euclidean distance
  RawCosineScorer(BaseScorer)        # B2: cosine similarity
  ZNormScorer(BaseScorer)            # N1: z-norm pada cosine
  TNormScorer(BaseScorer)            # N2: t-norm pada cosine
  SNormScorer(BaseScorer)            # N3: s-norm (satu arah)
  ASNormScorer(BaseScorer)           # N4: AS-norm (symmetric)
    __init__(cohort: ndarray, K: int)

  Perbedaan B0 vs B1 pada evaluasi (bukan di scorer, tapi di evaluation loop):
  - B0: score(user) = mean_{i=1..E}[-euclidean(enrol_i, probe)] — mean across
  individual embeddings
  - B1: score(user) = -euclidean(centroid(enrol_1..E), probe) — single centroid
  - B2/N1-N4: score(user) = scorer(centroid(enrol_1..E), probe) — centroid +
  scorer

  Cohort setup untuk N1-N4:
  scripts/07_evaluate_single.py:
  1. Load cohort pool (data/processed/cohort_pool.npz)
  2. Sample N_cohort users (default: 1000, swept kemudian)
  3. Cache cohort embeddings → results/cohort/cohort_embeddings_{hash}.npy
  4. Instantiate scorer dengan cohort
  5. Run evaluation loop untuk E ∈ {1,2,5,7,10}
  6. Sweep K untuk AS-Norm pada validation set
